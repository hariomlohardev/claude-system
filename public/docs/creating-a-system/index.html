Creating a System

A System is a versioned bundle of CLAUDE.md, skills, agents, commands, hooks and config that together form a reproducible Claude Code environment. Copy the template, fill the manifest, validate locally — then open a PR.

Scope reminder from CLAUDE.md: claude-system is the ecosystem/package layer around Claude Code. It never replaces Claude Code — it prepares an environment and shells out to the real claude CLI.

Minimum required files

Every System lives under systems/<name>/ where <name> is kebab-case. Folder name must exactly equal the "name" field in system.json — CI fails on mismatch.

A valid System must contain at minimum:

systems/<name>/
├── system.json   # required — manifest, validates against schemas/system.schema.json
├── CLAUDE.md     # required — prompt injected at session start
└── README.md     # required — human docs for GitHub

Optional:

├── skills/       # optional — Claude Code skills
├── agents/       # optional — subagents
├── commands/     # optional — slash commands
├── hooks/        # optional — hooks
└── settings.json # optional — Claude Code settings overrides

Both template/starter-system/ (copy-me template) and systems/example-system/ (CI fixture) demonstrate minimal structure. Prefer copying the template:

cp -r template/starter-system systems/my-new-system

system.json — field by field

system.json validates against schemas/system.schema.json (draft-07, additionalProperties: false — unknown fields rejected). Keep it in sync with the template.

Required fields

FieldConstraintsNotes
namekebab-case ^[a-z0-9]+(?:-[a-z0-9]+)*$, 1–64, must equal folderUnique across registry. CI checks folder equality.
displayName1–80 charsHuman title in list/info/search.
versionsemver 2.0.01.0.0, 0.1.0, 2.3.1-beta.1.
description10–300 charsOne-to-two-sentence summary for registry.
keywords1–15 items, 1–32 chars, uniquee.g. ["open-source","review"] — used by search.
author{name, github?, url?}name required 1–80; github handle without @; url https.
licenseSPDX 1–64MIT, Apache-2.0.
claudeSystem.specVersionsemverSpec version, e.g. 1.0.0.
permissionsenum uniqueHonest superset — see next section.

Optional fields

FieldNotes
categoryEnum: open-source, frontend, backend, testing, security, docs, research, devops, other.
repositoryOptional https URI of author's own repo. Omit if you live only in this monorepo — that's normal.
bugs.urlWhere issues for this System go. If omitted, default is this monorepo's issues.
homepageDocs or landing page.
dependencies{name,version}[] — keep empty unless you truly depend.
repository / bugs fallback: repository is optional. If you maintain only in this monorepo, omit it. bugs.url default is this monorepo /issues tagged with System name — not repository + "/issues".

Permissions — declare honestly

permissions is self-declared — reviewed during PR but not sandboxed at runtime (see Security). Declare the honest superset:

PermissionMeaning
filesystem:readReads files outside installed folder
filesystem:writeWrites or mutates files
network:readOutbound fetch/clone
network:writePushes data out
shell:execExecutes shell commands/scripts
credentials:readAccesses credentials/tokens

Testing locally before a PR

Validate at least these checks before pushing — they mirror validate.yml in CI:

# schema
node cli/dist/index.js validate systems/<name>
# folder-name rule
name=$(jq -r .name systems/<name>/system.json); [ "$name" = "<name>" ] && echo ok
# required files
test -f systems/<name>/system.json && test -f systems/<name>/CLAUDE.md && test -f systems/<name>/README.md && echo "required files ok"
# preview registry (restore before committing)
node scripts/generate-index.js
cat registry/index.json | jq '.systems[] | select(.name=="<name>")'
git restore registry/index.json

PR flow

StepWhat happens
1 · Fork & branchgit checkout -b system/<your-name>
2 · Copy templatecp -r template/starter-system systems/<your-name>
3 · Editsystem.json, CLAUDE.md, README.md — change all placeholders.
4 · ValidateSchema, folder rule, required files, security scan — mirror validate.yml.
5 · Open PRTitle Add system: <your-name>, describe permissions.
6 · CIvalidate.yml must be green — never bypass.
7 · Mergeregistry/index.json regenerated; users search/install/run.

registry/index.json is generated — never hand-edit

Built by scripts/generate-index.js from systems/*/system.json. The small file the CLI fetches. Do not edit in a System PR — edit your system.json instead; restore before committing (git restore registry/index.json).
