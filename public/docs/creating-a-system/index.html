Creating a System

Copy the starter, fill the manifest, validate locally — then open a PR. The spec wins over convenience.

A System is a versioned, distributable bundle of CLAUDE.md, skills, agents, commands, hooks, and config that together form a reproducible, purpose-built Claude Code environment — for example an “open-source contributor” setup or a “frontend development” setup. The formal contract is defined in SYSTEM_SPEC.md; this guide is the contributor-facing how-to. When in doubt, the spec wins.

Scope reminder: claude-system is the ecosystem/package layer around Claude Code. It never replaces Claude Code — it prepares an environment and shells out to the real claude CLI.

Minimum required files

Every System lives under systems/<name>/ where <name> is the kebab-case id. Folder name must exactly equal the "name" field in system.json — CI enforces this and will fail your PR on a mismatch.

A valid System must contain at minimum:

systems/<name>/
├── system.json   # required — manifest, validates against schemas/system.schema.json
├── CLAUDE.md     # required — prompt injected into Claude Code at session start
└── README.md     # required — human docs for browsing on GitHub

Additional folders are optional — add them only if you need them:

├── skills/       # optional — Claude Code skills
├── agents/       # optional — subagents
├── commands/     # optional — slash commands
├── hooks/        # optional — hooks
└── settings.json # optional — Claude Code settings overrides

Both template/starter-system/ (the copy-me template) and systems/example-system/ (a permanently-valid CI fixture) demonstrate the minimal structure. Prefer copying the template:

cp -r template/starter-system systems/my-new-system

system.json — field by field

system.json validates against schemas/system.schema.json (JSON Schema draft-07, additionalProperties: false at every level — unknown fields are rejected). The schema and this doc, plus template/starter-system/, must never drift apart.

Required fields

FieldConstraintsNotes
namekebab-case ^[a-z0-9]+(?:-[a-z0-9]+)*$, 1–64 chars, must equal folder nameUnique across the registry. CI checks uniqueness and folder equality.
displayName1–80 charsHuman title shown in list/info/search.
versionsemver 2.0.01.0.0, 0.1.0, 2.3.1-beta.1. Bump following semver.
description10–300 charsOne-to-two-sentence summary shown in registry.
keywords1–15 items, 1–32 chars, uniqueLowercase terms, e.g. ["open-source","review","pr"].
author{name, github?, url?}name 1–80 chars required; github handle without @; url https URI.
licenseSPDX 1–64 charse.g. MIT, Apache-2.0.
claudeSystem.specVersionsemverSpec version, e.g. "1.0.0".
permissionsenum, uniqueSee next section — honest superset.

Optional fields

FieldNotes
categoryEnum: open-source, frontend, backend, testing, security, docs, research, devops, other.
repositoryOptional https URI of author's own repo. Omit if you live only in this monorepo — that's normal.
bugs.urlWhere issues for this System should go. If omitted, default is this monorepo's issues.
homepageDocs or landing page.
dependencies{name,version}[] — keep empty unless you truly depend. Multi-system resolution beyond simple case is out of scope for v1.
repository / bugs fallback: repository is optional. If you maintain only in this monorepo, omit it. If bugs is omitted, tooling treats default as this monorepo /issues tagged with the System name — it does NOT assume repository + "/issues".

Permissions — declare honestly

permissions is a self-declared list — reviewed during PR but not sandboxed at runtime (see Security). Declare the honest superset:

PermissionMeaning
filesystem:readReads files outside the installed System folder
filesystem:writeWrites or mutates files
network:readMakes outbound network requests (fetch, clone)
network:writeSends data out / pushes
shell:execExecutes shell commands or scripts
credentials:readAccesses credentials, tokens, or secrets

Rules: default to least privilege (start with []), if hooks run exec you need shell:exec, reviewers will compare permissions against skills/, agents/, commands/, hooks/, and CLAUDE.md.

Testing locally before a PR

# schema
node cli/dist/index.js validate systems/<name>
# folder-name rule
name=$(jq -r .name systems/<name>/system.json); [ "$name" = "<name>" ] && echo ok
# required files
test -f systems/<name>/system.json && test -f systems/<name>/CLAUDE.md && test -f systems/<name>/README.md && echo "required files ok"
# preview registry
node scripts/generate-index.js
cat registry/index.json | jq '.systems[] | select(.name=="<name>")'
git restore registry/index.json

4 · ValidateSchema, folder rule, required files, security scan — mirror what validate.yml does.
5 · Open PRTitle Add system: <your-name>. Fill the template, describe permissions.
6 · CIvalidate.yml must be green — never ask to bypass.
7 · Mergeregistry/index.json regenerated; users can search/install/run.
