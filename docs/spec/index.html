System Spec

Draft contract — what the registry and CLI guarantee, and where v1 stops.

Status: draft — when in doubt, the spec wins over convenience (see CLAUDE.md).

What a System is

A System is a versioned, distributable bundle of CLAUDE.md, skills, agents, commands, hooks, and configuration that together form a reproducible, purpose-built Claude Code environment. Examples: “open-source contributor”, “frontend development”. It configures Claude Code; it does not replace it.

Each System lives under systems/<name>/ where <name> is kebab-case and must equal system.json:name. Required files: system.json + CLAUDE.md + README.md. Optional: skills/, agents/, commands/, hooks/, settings.json.

Manifest and validation

system.json validates against schemas/system.schema.json (draft-07, additionalProperties: false everywhere). Unknown fields are rejected. schemas/system.schema.json, docs/creating-a-system.md, and template/starter-system/ must stay in sync.

CI (validate.yml) enforces: schema validity, name === folder, required files present, unsafe hooks/scripts, registry/index.json not hand-edited, permissions vs setup.sh and # WHY:, and that template/starter-system still validates.

Registry

registry/index.json is generated by scripts/generate-index.js from systems/*/system.json and validated against schemas/registry-index.schema.json. It is the only file the CLI fetches directly (via /api/registry on Vercel with s-maxage=60 and fallback to raw.githubusercontent.com) — not the whole repo. Never hand-edit it in a System PR.

Install and run

claude-system install <name> copies to ~/.claude-system/systems/<name>/ and records {version, installedAt, setupDone} in ~/.claude-system/systems.json. claude-system run <name> [-- <args>] opens the real claude CLI inside that directory, forwarding extra args.

If the System ships setup.sh, it must contain # WHY:, declares shell:exec, and is shown once with a y/N prompt. Only on exit 0 is setupDone set; otherwise next run re-prompts.

What is out of scope for v1

Per §46: no web marketplace, no cloud backend, no custom AI runtime, no full GUI, no multi-system dependency resolution beyond the simple case, no enterprise auth. MVP first — keep the CLI thin; what can be a System, a Skill, or a plugin, build as one of those.

Conventions

Language: TypeScript on Node, commander + zod + simple-git/execa, native fetch. Security is explicit — never silently grant permissions or execute scripts. Session/config integration uses only documented, supported Claude Code interfaces.

Full text is SYSTEM_SPEC.md on GitHub — this page is a condensed, airy rendering of it.
